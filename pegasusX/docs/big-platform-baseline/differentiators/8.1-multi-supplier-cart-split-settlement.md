# 8.1 Unified Multi-Supplier Cart + Delivery-Triggered Split Settlement

> **PLANNING BASELINE** — not living runtime status. Prefer [`../DOCS_SOURCE_OF_TRUTH.md`](../DOCS_SOURCE_OF_TRUTH.md) and code for what is shipped.


## Problem

Retailers buy from multiple suppliers in one shopping session. Incumbents force per-supplier checkout or settle too early (before delivery/fiscal).

## Solution

1. One cart across suppliers → single checkout.  
2. System creates **per-supplier orders** + split payment instructions.  
3. Money / credit moves only when each leg reaches **arrival + payment choice + fiscal success** (or policy-defined majority).  

## How it works

```
CartSession (parent)
  ├─ Order supplier A  (own inventory, own fiscal)
  ├─ Order supplier B
  └─ SettlementPlan (split instructions, minor units)
```

- Inventory reserved per supplier warehouse.  
- Fiscal per order (EHF/regime later).  
- Partial failure: refund/credit adjust only completed legs; cancel residuals with inventory release.

## Edge cases

| Case | Rule |
|------|------|
| One supplier OOS | Drop or backorder that leg; reprice remaining |
| One fiscal fail | That leg FISCAL_FAILED; others may COMPLETED |
| Split pay 40/60 | Integer split with remainder to last leg |
