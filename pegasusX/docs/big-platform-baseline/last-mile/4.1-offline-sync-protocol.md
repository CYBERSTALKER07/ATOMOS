# Shop-Closed / Partial / Proximity — Offline Sync Protocol

## Principles

1. **Idempotency-Key** is the sole dedupe key (route + key + auth subject).
2. **Client timestamp** records original doorstep time; server commit clock still owns Spanner `UpdatedAt`.
3. **Retailer response wins** over timeout if order still `ARRIVED_SHOP_CLOSED` when either commits.
4. **No double-release** on partial offload replay: same lines + same Idempotency-Key → cached response.

## Queued actions (driver)

| Action | Endpoint | Offline fields |
|---|---|---|
| Mark shop closed | `POST /v1/delivery/shop-closed` | `client_timestamp`, reason, photo_url, lat/lng |
| Proximity unlock | `POST /v1/delivery/proximity-unlock` | `client_timestamp` (max age 2m for anti-spoof) |
| Partial offload | `POST /v1/delivery/partial-offload` | `client_timestamp`, `signed_nonce` |
| Credit leave | `POST /v1/delivery/credit-delivery` | `force_bypass_token` if no unlock |
| Cash collect | `POST /v1/order/collect-cash` | lat/lng must still satisfy ≤100 m if unlock missing |

## Reconnect order

1. Flush proximity unlock (if GPS still valid).
2. Flush shop-closed / partial with original timestamps.
3. Flush settlement (cash / credit) only after unlock succeeds or live coords pass.

## Keys (aligned packages + native)

- `driver-report-shop-closed:{driverId}:{orderId}`
- `driver-proximity-unlock:{driverId}:{orderId}`
- `driver-partial-offload:{driverId}:{orderId}:{hash(lines)}`
- `driver-credit-delivery:{driverId}:{orderId}`
- `driver-collect-cash:{driverId}:{orderId}`
