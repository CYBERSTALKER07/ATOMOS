# 4.5 Proximity Settlement

## Rule

Without proximity unlock, the driver **cannot** collect cash or leave on credit (except supervised `FORCE_BYPASS` with shop-closed bypass token).

## Unlock

`POST /v1/delivery/proximity-unlock`

```json
{
  "order_id": "…",
  "latitude": 41.31,
  "longitude": 69.28,
  "client_timestamp": "2026-07-29T12:00:00Z",
  "force_bypass_token": "optional-6-digit"
}
```

Unlock methods:

| Method | Rule |
|---|---|
| `H3` | Driver cell matches order H3 (res 9 / parent-compatible) |
| `GEOFENCE_100M` | Haversine ≤ 100 m of order lat/lng |
| `FORCE_BYPASS` | Valid `ShopClosedAttempts.BypassToken` for open BYPASS_ISSUED |

Anti-spoof: `client_timestamp` age ≤ 2 minutes when provided.

On success: sets `Orders.ProximityUnlockedAt` + `ProximityMethod`, outbox `PROXIMITY_UNLOCKED`.

## Payment guards

- `POST /v1/order/collect-cash` — requires unlock **or** live settlement proximity on request coords.
- `POST /v1/delivery/credit-delivery` — requires unlock **or** `force_bypass_token`; also re-checks credit profile ACTIVE + available ≥ amount.

Approach geofence (500 m) remains for QR/arrival UX; settlement is the tighter gate.
