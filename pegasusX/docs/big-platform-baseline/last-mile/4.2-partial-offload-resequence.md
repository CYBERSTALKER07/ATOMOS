# 4.2 Partial Offload + Resequence

## Contract

`POST /v1/delivery/partial-offload`

```json
{
  "order_id": "…",
  "lines": [
    { "sku": "SKU1", "delivered_qty": 7, "remaining_qty": 3, "reason": "SHOP_REFUSED" }
  ],
  "client_timestamp": "…",
  "signed_nonce": "optional offline nonce"
}
```

Rules:

- `delivered_qty + remaining_qty == original quantity` (enforced).
- Reasons: `DAMAGED | MISSING | SHOP_REFUSED | CAPACITY | OTHER`.
- Money / fiscal: only delivered portion (`TotalMinor` rewritten to delivered minor; `OriginalTotalMinor` preserved).
- Inventory: remaining stays reserved / return flow (full release path TBD with resequence).
- Offline: Idempotency-Key + optional `signed_nonce`; no double-release on replay.

## Storage

No `OrderLines` table. Fields on `LineItemsJson`:

- `delivered_qty`, `remaining_qty`, `offload_status` (`FULL|PARTIAL|NONE|RETURNED`), `offload_reason`
- Order flag: `Orders.PartialDelivery`

Event: `PARTIAL_OFFLOAD` (outbox + best-effort WS fan-out).

## Resequence

After partial, driver may call existing `POST /v1/fleet/route/reorder` with remaining stops (+ optional warehouse return stop). Dedicated return-stop injection is a follow-up.
