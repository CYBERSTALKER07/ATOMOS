# 2.1 Causal Demand Sensing + External Signals

## Inputs

| Signal | Source |
|--------|--------|
| Historical velocity | Order lines Spanner |
| Promotions | Supplier promotions |
| Weather / public events | External APIs (Phase 1 partners) |
| Competitor price | Scrape/partner (policy-governed) |
| Retailer auto-order rules | Retailer settings |

## Grain

`warehouse_id × sku_id` (+ optional H3 cell for last-mile demand).

## Outputs

- Probability distribution (p10/p50/p90) + **confidence** (existing forecast-confidence patterns).  
- Not only point forecasts.  
- Event: `DEMAND_SIGNAL` (new) with contribution breakdown (“why”).

## How it works

1. Nightly + intraday jobs on **ai-worker** / planning packages.  
2. Publish signals → Kafka.  
3. Retailer/supplier UIs show recommended orders with explanations.  
4. Accept still goes through normal checkout/order APIs.

## Edge cases

| Case | Rule |
|------|------|
| Cold start SKU | High uncertainty band; no auto-commit |
| Signal feed down | Fall back to velocity-only model |
| Promo double-count | Attribution model tags exclusive contributions |
