# 2.2 Multi-Echelon Inventory Optimization (MEIO)

> **PLANNING BASELINE** — not living runtime status. Prefer [`../DOCS_SOURCE_OF_TRUTH.md`](../DOCS_SOURCE_OF_TRUTH.md) and code for what is shipped.


## Objective

Optimize safety stock + reorder points across **factory → warehouse → (retailer demand)** under:

- Lead times (supply lanes)  
- Capacity  
- Service-level targets  
- **Credit risk tiers** (PegasusX differentiator)  

## How it works

1. Snapshot knowledge graph.  
2. Solver (OR-Tools when `optimizer-core` is healthy; else heuristic) produces recommended positions — see [`../../OPTIMIZER_AND_ROUTING_RUNTIME.md`](../../OPTIMIZER_AND_ROUTING_RUNTIME.md).  
3. Results become:  
   - Replenishment requests (warehouse → factory), and/or  
   - Suggested auto-order rule changes (retailer).  
4. **Human or policy accept** before mutation.

## Existing anchors

- Supplier MEIO network summary API  
- Replenishment policies / trigger  
- Warehouse supply requests  

## Math sketch

```
SS_i = z * σ_leadtime_demand_i
ROP_i = demand_leadtime_i + SS_i
subject to: Σ inventory_value <= capital_cap
            credit_blocked retailers excluded from credit-funded demand
```

All money in **minor units**.
