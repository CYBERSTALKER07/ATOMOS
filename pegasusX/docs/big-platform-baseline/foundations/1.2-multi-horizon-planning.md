# 1.2 Multi-Horizon Planning Engine

## Horizons

| Horizon | Name | Cadence | Output |
|---------|------|---------|--------|
| Strategic | Network design | Quarterly / ad-hoc | Warehouse/factory placement, zone radius |
| Tactical | S&OP / MEIO | Weekly–monthly | Safety stock, replenishment policies |
| Operational | Dispatch | Intra-day / continuous | Routes, manifests, locks |
| Execution | Real-time replan | Seconds–minutes | Resequence, rescue, reassign |

## Solver-agnostic contract

```
PlanRequest {
  horizon, scenario_id, objective_weights (cost, service, carbon),
  graph_snapshot_ref, constraints[]
}
PlanResult {
  scenario_id, version, status (DRAFT|PUBLISHED|REJECTED),
  decisions[], metrics{}, optimizer_source (OR_TOOLS|HEURISTIC|GPU_FUTURE)
}
```

- **OR-Tools** via existing `optimizer-core` sidecar when healthy.  
- **Heuristic fallback** always required (SSMR already patterns this for dispatch).  
- Plans are **versioned**, **scenario-branchable**, published as Kafka events.

## Execution consumption

- Execution may **accept** published plan (materialize routes/manifests) or **reject** with reason.  
- Never auto-mutate money/inventory from a plan without going through order/inventory APIs.

## Edge cases

| Case | Rule |
|------|------|
| Optimizer down | Heuristic + `optimizer_source` flag |
| Stale snapshot | Plan includes snapshot generation time; reject if inventory drifted beyond policy |
| Concurrent publish | Scenario version CAS / unique published baseline per scope |
