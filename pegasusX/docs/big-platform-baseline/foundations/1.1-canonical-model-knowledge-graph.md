# 1.1 Unified Canonical Model + Lightweight Knowledge Graph

> **PLANNING BASELINE** — not living runtime status. Prefer [`../DOCS_SOURCE_OF_TRUTH.md`](../DOCS_SOURCE_OF_TRUTH.md) and code for what is shipped.


## Goal

Single source of truth for planning **and** execution. No ad-hoc joins that diverge from order/inventory truth.

## Nodes (entities)

| Node | Existing anchors | Extensions |
|------|------------------|------------|
| **Product / SKU** | Catalog products, unit volume VU | Affinity, temperature class, velocity class |
| **Location** | Warehouse, factory, H3 cell, retailer address | Dock door, slot, yard spot |
| **Party** | Supplier, Retailer, Driver, staff roles | Carrier (future), OFD operator |
| **InventoryPosition** | OnHand, Reserved per warehouse×SKU | In-transit, staged, quarantined |
| **Order / OrderLine** | Orders table + line JSON | Parent cart session (multi-supplier) |
| **Constraint** | Credit limit, freeze lock, capacity | Labor skill, fiscal regime version |
| **Cost** | Unit price minor, ledger | Lane cost, carbon proxy |
| **Capacity** | Vehicle VU, driver on-shift | Shift slots, dock appointments |

## Edges (first-class relationships)

| Edge | Meaning |
|------|---------|
| SupplyLane | Factory → warehouse (lead time, capacity) |
| DeliveryZoneMembership | Retailer H3 ∈ supplier zone snapshot |
| CreditProfile | Retailer↔Supplier limit/balance/status |
| FulfillsFrom | Order → warehouse (resolver) |
| AssignedTo | Order → driver/manifest |
| FiscalRegimeAtComplete | Order → TaxRegimeVersion |
| ClaimOf | Claim → OrderLine(s) |
| ReverseOf | Return ticket → claim/order |

## How decisions use the model

- **Planning** reads graph snapshots (read-only Spanner + optional Redis projection).  
- **Execution** mutates positions/orders with existing txn+outbox laws.  
- **Intelligence** links anomalies to nodes/edges (claim spike → SKU + warehouse + driver).

## Implementation notes (PegasusX)

- Prefer Spanner tables + explicit relationship tables over a separate graph DB for v1.  
- Optional Redis adjacency cache for control-tower queries.  
- Kafka events already name many edges (`ORDER_ASSIGNED`, `SUPPLY_REQUEST_*`, credit profile changed).

## Edge cases

| Case | Rule |
|------|------|
| Orphan edge | Foreign keys / soft-delete; never plan on missing node |
| Concurrent inventory edge | Same RW txn as order line reserve |
| Multi-tenant leak | Every node/edge scoped by `supplier_id` (or platform admin) |
